# 小说分析分块器 v1

这个工具解决一个单一问题：**长篇小说不适合一次性送入原版 NLP 分析器时，先按自然结构切成可分析的块。**

它不是最终的“参考片段检索切片器”。后续用于 RAG/参考片段检索的 500–1200 字级片段会单独设计。

## 当前规则

1. 优先识别 `第1章 标题`、`第一章 标题` 这类章节标题。
2. 默认不把第一章之前的书籍信息、简介等 preamble 放入分析块。
3. 正常章节保持完整，不从章节中间切开。
4. 只有单章本身超过 `--max` 时，才按段落继续切。
5. 极端情况下单个段落仍过长，最后才按中文句末标点切；不从一句话中间硬切。
6. 输出 `manifest.json`，记录每个分块的字符数、起止章节和是否发生章节内切分。

## 默认参数

- 目标大小：50,000 字符
- 建议最小：35,000 字符
- 建议最大：60,000 字符

## 用法

```bash
npm run chunk -- samples/target.txt --out work/target-chunks
```

可调整：

```bash
npm run chunk -- samples/target.txt \
  --out work/target-chunks \
  --target 50000 \
  --min 35000 \
  --max 60000
```

## 《老太》私有基线测试

测试原文未提交到 GitHub，只在私有工作区运行。

结果：

- 原始字符数：645,113
- 检测到章节标题：241
- 第一章前排除内容：643 字符
- 输出分析块：13
- 最小块：45,216 字符
- 最大块：51,225 字符
- 平均块：49,572 字符
- 被从章节内部切开的块：0

说明：源 TXT 的书籍信息写有 248 章，但正文实际可检测到的章节标题到第 241 章，且编号中缺少第 174 章。v1 按实际文本结构处理，不自行补章。
