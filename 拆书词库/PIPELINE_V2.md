# 网文拆书词库流水线 V2

## 目标

把整本网络小说转成“高召回单书词库”，再经过多书交叉统计形成最终通用词库。

V2 的核心变化：

- 不再一开始就追求“少而精”；
- 把召回率检查前置为硬门槛；
- LLM 负责语义发现，程序负责精确统计；
- 所有批次都有原文证据和 `resume_state`；
- 题材词、专名嫌疑、低频词先隔离，不直接丢弃。

## 总流程

```text
整本小说 TXT/MD
  ↓
章节解析
  ↓
按 10-20 章分批
  ↓
vocabulary-extractor-agent（高召回）
  ↓
候选词库
  ↓
vocabulary-coverage-auditor（只找遗漏）
  ├─ HIGH → 回到高召回取词
  ├─ MEDIUM → 定向补扫
  └─ LOW → 进入清洗
  ↓
清洗层
  ↓
分类复核
  ↓
Python/程序精确统计
  ↓
全书 QA
  ↓
单书完整词库
  ↓
多书交叉统计
  ↓
通用性评级 S/A/B/C
  ↓
核心通用词库 + 扩展词库 + 题材词库
```

## Stage 0：章节解析

要求：

- 识别 `第X章`、中文数字章、阿拉伯数字章、番外等常见结构；
- 保留内部文本块序号，不依赖章节号绝对连续；
- 重复章号、缺号、番外都不能造成正文丢失；
- 输出每块：内部块号、原章节标题、正文、字符数。

章节解析结果必须可复现。若结构异常，记录 warning，不修改原文。

## Stage 1：批次切分

默认 10-20 个内部文本块一批。

每批至少保存：

```json
{
  "book_id": "",
  "batch_id": "021-040",
  "block_start": 21,
  "block_end": 40,
  "source_chapters": [],
  "char_count": 0
}
```

## Stage 2：高召回取词

调用 `agents/vocabulary-extractor-agent.md`。

本阶段不判断最终通用性，不做 S/A/B/C。

只判断：

> 是否真实出现 + 是否能独立成词 + 是否未来可能用于网文写作。

输出：`NEW`、`EXISTING_HIT`、`REVIEW`、`REVIEW_PROPER_NOUN`、`genre_words`、`resume_state`。

## Stage 3：Coverage 漏词审计

调用 `agents/vocabulary-coverage-auditor.md`。

它必须看同一批正文，但只做“找遗漏”。

门控：

- LOW：可继续；
- MEDIUM：再补扫一次；
- HIGH：本批判定未完成，重新高召回扫描。

特别规则：即使遗漏比例不高，只要还成片漏掉普通动作、基础词、生活名物、称谓关系，也判 HIGH。

## Stage 4：候选合并

所有批次进入同一个 `master_candidate`。

合并键：`word`。

不能因为同一词跨类别出现就创建多个词条；使用 `categories` 多标签。不能合并近义词。批次只记录首次发现点，精确全书频次后算。

## Stage 5：清洗

清洗重点：人名/昵称、具体地名、公司/平台/品牌、门派/功法/法宝/系统等世界专名、章节标题污染、错误分词、句子残片、普通自由组合短语、无意义数字/符号/URL。

清洗原则：

> 不确定就放 REVIEW，不要静默删除。

题材词进入题材层，不进入垃圾层。

## Stage 6：分类复核

使用统一 A-U 分类，允许多标签。

## Stage 7：程序精确统计

LLM 不负责精确计数。

程序对完整小说正文计算：

- `book_frequency`
- `chapter_coverage`
- 每章出现情况
- 后续多书的 `book_coverage`
- `per_book_frequency`

统计对象必须来自已确认词表，避免粗暴 n-gram 把大量垃圾当词。

## Stage 8：全书 QA

整本小说全部批次完成后，再做四轮 QA：

1. 分类回扫：按动作/神态/心理/名物等重新找遗漏；
2. 高频缺失检查：正文反复出现但候选表没有的词；
3. 低频复核：低频 ≠ 无价值；
4. 污染检查：专名、短语、错误切词、标题残留。

只有 QA 完成后，才允许标记单书词库 `FROZEN_V1`。

## Stage 9：多书交叉

每本书先独立达到高召回，不要用第一本书的词表限制第二本书的发现范围。

多书完成后统计：作品覆盖数、章节覆盖、总词频、题材分布、作者特色倾向。

优先级：

```text
作品覆盖数 > 章节覆盖 > 总词频
```

## Stage 10：评级

- S：多书稳定出现、跨题材能力强、写作调用价值高；
- A：常用、适用面广；
- B：低一些但明确有用；
- C：明显题材化、作者化或适用范围有限。

8000 只是目标量级，不是硬配额。

## 断点续跑

每完成一个批次立即保存：

```json
{
  "book_id": "",
  "processed_blocks": 40,
  "current_unique_words": 0,
  "last_completed_batch": "021-040",
  "next_batch": "041-060",
  "coverage_status": "LOW",
  "rule_version": "V2",
  "warnings": []
}
```

恢复优先级：

```text
STATE > 单书执行 LOG > 汇总 CHECKPOINT
```

不得仅凭聊天记忆恢复进度。

## 完成定义

“跑完章节”不等于“词库完成”。

单书完成必须同时满足：所有正文块已处理、每批 coverage 门控通过、所有新增词可追溯到原文、全书 QA 完成、程序统计完成、专名/题材/待确认已隔离、STATE 标记为 frozen。
